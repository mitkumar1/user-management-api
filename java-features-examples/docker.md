# Blue-Green Deployment on Azure (Zero Downtime)

## What is Blue-Green Deployment?
Blue-green deployment is a release management strategy that reduces downtime and risk by running two identical production environments (Blue and Green). Only one environment serves live traffic at a time. New versions are deployed to the idle environment, tested, and then traffic is switched over.

## Step-by-Step: Blue-Green Deployment on Azure Kubernetes Service (AKS)

### 1. **Prepare Two Environments**
     - Deploy two identical Kubernetes deployments/services: `blue` (current live) and `green` (new version).
     - Both can exist in the same cluster, using different labels (e.g., `app=web, version=blue` and `app=web, version=green`).

### 2. **Deploy the Blue Environment**
     - Deploy your current stable app as the `blue` deployment and expose it via a Kubernetes Service (e.g., `web-service`).

### 3. **Deploy the Green Environment**
     - Deploy the new app version as the `green` deployment, but do not route traffic to it yet.

### 4. **Test the Green Environment**
     - Access the `green` deployment directly (using a temporary service or port-forward) to run tests and health checks.

### 5. **Switch Traffic (Zero Downtime)**
     - Update the selector of the `web-service` to point from `version=blue` to `version=green`.
     - This instantly routes all new traffic to the green deployment with no downtime.

### 6. **Monitor and Rollback if Needed**
     - Monitor the green deployment for errors.
     - If issues occur, switch the service selector back to `version=blue` for instant rollback.

### 7. **Clean Up**
     - Once satisfied, delete the blue deployment or keep it for the next cycle.


## Example YAML for Blue-Green Deployment

**Blue Deployment:**
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
    name: web-blue
spec:
    replicas: 3
    selector:
        matchLabels:
            app: web
            version: blue
    template:
        metadata:
            labels:
                app: web
                version: blue
        spec:
            containers:
            - name: web
                image: myorg/web:1.0
```

**Green Deployment:**
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
    name: web-green
spec:
    replicas: 3
    selector:
        matchLabels:
            app: web
            version: green
    template:
        metadata:
            labels:
                app: web
                version: green
        spec:
            containers:
            - name: web
                image: myorg/web:2.0
```

**Service (Switch Selector for Cutover):**
```yaml
apiVersion: v1
kind: Service
metadata:
    name: web-service
spec:
    selector:
        app: web
        version: blue # Change to green for cutover
    ports:
    - port: 80
        targetPort: 80
```

## Azure-Specific Tips
- Use Azure DevOps Pipelines or GitHub Actions for automated deployments.
- Use Azure Traffic Manager or Application Gateway for advanced traffic routing if needed.
- AKS supports zero-downtime deployments with this pattern.

---

**Summary:**
Blue-green deployment on Azure (or any Kubernetes) enables zero-downtime releases by switching traffic between two environments. It is ideal for mission-critical apps where availability is key.
# Docker & Kubernetes Interview Questions and Answers

## Docker

1. **What is Docker?**
   - Docker is a platform for developing, shipping, and running applications in lightweight containers.

2. **What is a Docker container?**
   - A container is a lightweight, standalone, executable package that includes everything needed to run a piece of software.

3. **What is a Docker image?**
   - An image is a read-only template used to create containers.

4. **What is Dockerfile?**
   - A Dockerfile is a text file with instructions to build a Docker image.

5. **How do you build a Docker image?**
   - Using `docker build -t image_name .`

6. **How do you run a Docker container?**
   - Using `docker run image_name`

7. **What is Docker Hub?**
   - Docker Hub is a cloud-based registry for sharing Docker images.

8. **How do you list running containers?**
   - `docker ps`

9. **How do you stop a running container?**
   - `docker stop <container_id>`

## Kubernetes

26. **What is Kubernetes?**
    - Kubernetes is an open-source platform for automating deployment, scaling, and management of containerized applications.

27. **What is a Pod in Kubernetes?**
    - A Pod is the smallest deployable unit in Kubernetes, which can hold one or more containers.

28. **What is a Deployment?**
    - A Deployment manages a ReplicaSet and provides declarative updates for Pods.

29. **What is a Service in Kubernetes?**
    - A Service exposes a set of Pods as a network service.

30. **What is a ConfigMap?**
    - ConfigMap is used to store non-confidential configuration data in key-value pairs.

31. **What is a Secret?**
    - Secret is used to store sensitive data such as passwords, tokens, and keys.

32. **What is a Namespace?**
    - Namespace is a way to divide cluster resources between multiple users.

33. **What is a ReplicaSet?**
    - Ensures a specified number of pod replicas are running at all times.

34. **What is a StatefulSet?**
    - Manages stateful applications, giving each pod a unique identity and stable storage.

35. **What is a DaemonSet?**
    - Ensures that all (or some) nodes run a copy of a pod.

36. **What is a Job in Kubernetes?**
    - A Job creates one or more pods and ensures they complete successfully.

37. **What is a CronJob?**
    - A CronJob runs jobs on a scheduled time.

38. **How do you scale a deployment?**

39. **How do you update a deployment?**
    - `kubectl set image deployment/<name> <container>=<new_image>`

40. **How do you roll back a deployment?**
    - `kubectl rollout undo deployment/<name>`

41. **What is a PersistentVolume (PV)?**
    - A piece of storage in the cluster provisioned by an admin or dynamically provisioned.

    - A request for storage by a user.

43. **What is a Helm chart?**
    - A package manager for Kubernetes applications.

44. **What is kubelet?**
    - An agent that runs on each node and ensures containers are running.

45. **What is etcd?**
    - A distributed key-value store used for Kubernetes cluster state.

46. **What is the difference between ReplicaSet and StatefulSet?**
    - ReplicaSet is for stateless pods; StatefulSet is for stateful pods with stable identity and storage.

47. **How do you expose a deployment as a service?**
    - `kubectl expose deployment <name> --type=NodePort --port=80`

48. **What is Ingress?**
    - Ingress manages external access to services, typically HTTP.

49. **How do you check the status of pods?**
    - `kubectl get pods`

50. **How do you delete a pod?**
    - `kubectl delete pod <pod_name>`
